## Exact attach and query

Run from the project directory after `uv sync --frozen`. `duckdb_runtime.database()`
creates an in-memory stock DuckDB connection with extension binaries and
repository registration confined to `.cache/duckdb/`, then executes:

```sql
SET allow_extension_repositories = 'allowed';
CREATE EXTENSION REPOSITORY IF NOT EXISTS query_farm
    WITH PREFIX 'https://duckdb-extensions.query.farm';
INSTALL vgi FROM query_farm;
LOAD vgi FROM query_farm;

ATTACH 'github' AS github
    (TYPE vgi, LOCATION '.venv/bin/python github_worker.py');
SELECT * FROM github.main.releases('duckdb', 'duckdb');
DETACH github;
```

For example, execute a direct release query with the project's engine setup:

```sh
uv run --frozen python - <<'PY'
from duckdb_runtime import database
with database() as con:
    con.execute("ATTACH 'github' AS github (TYPE vgi, LOCATION '.venv/bin/python github_worker.py')")
    print(con.sql("SELECT * FROM github.main.releases('duckdb', 'duckdb')"))
    con.execute("DETACH github")
PY
```

`demo.sql` contains the complete inventory query. It materializes one releases
scan for `duckdb/duckdb` before joining the local CSV, filters out prereleases and
missing publication dates, and selects the most recently published row by
casting `published_at` to `TIMESTAMPTZ`. It compares tags only for inequality,
not as ordered versions. Matching tags and unrelated repositories are excluded.
If no dated non-prerelease is fetched, the query returns no rows.

The standalone worker launch command is `.venv/bin/python github_worker.py`.
Its stdout carries Arrow protocol bytes; use it through `ATTACH`. Diagnostics
belong on stderr.

## Limits and behavior

- Each scan follows GitHub's `Link: ...; rel="next"` pagination, requests five
  releases per page, and stops after three pages: at most 15 releases, **not a
  full release history**. An empty page or absent next link ends the scan.
- Requests are unauthenticated GETs with an explicit User-Agent, API version,
  and a 10-second socket timeout. There are no retries. No tokens, `gh auth`,
  netrc, cookies, or environment proxies are consulted. HTTP redirects are
  reported as errors; use the repository's current owner and name.
- NULL, empty names, spaces, or path separators are rejected. Required fields
  with missing or incorrect types fail the query. HTTP status codes and
  rate-limit retry hints appear in errors rather than becoming empty results.
- Pagination stays on the same API origin and release endpoint, including
  GitHub's numeric repository URL form. Repeated links are rejected.
- `inventory.csv` is fictional sample data. A tag difference is a review
  candidate; it does not establish version order or a safe upgrade.
- A direct subprocess is started for each attachment. There is no worker pool,
  persistent API cache, per-inventory-row API call, upload, or deployment.
